# CT Signal — the questions Connecticut is asking, answered with data

Hack for Humanity · Challenge 4: CTData.org, Made Conversational

## Problem

CTData publishes and curates Connecticut's community data, but the data is
passive: it waits at ctdata.org for someone who already knows to look. The
organization literally staffs a human "Ask a Data Question" Data Helpline —
proof that people want answers and can't get to them. Meanwhile, people *do*
pay attention when a story breaks: rents, schools, jobs, crime, elections.
The moment a topic is top-of-mind is exactly when CT data could ground the
conversation — and it passes by.

**Who this affects:** CTData's audience (nonprofit staff, town employees,
journalists, advocates, residents) who never visit a data portal, and CTData
itself, whose mission ("connecting people and data for good", equity focus,
existing weekly newsletter) is gated by that last mile of attention.

## Solution

A continual loop that makes CTData conversational in reverse — the system
asks the questions:

1. **Listen** to news signals (CT + national RSS) and a civic calendar (Nov 3, 2026 election).
2. **Generate** a question per headline — constrained to a hand-curated
   catalog, so the model can only propose questions that are *answerable*.
3. **Answer** by executing real queries (Data Commons for the 50-state
   stack-up + CT places; CT Socrata for town-level local flavor). No number
   in a card is generated by an LLM.
4. **Publish** "CT Stack-Up" / "Connecticut Numbers" cards to a growing
   feed: headline → question → query → number → chart → citation.

Two streams, one pipeline:
- **Stream A (local):** CT headlines → CT-only questions (Socrata town data).
- **Stream B (stack-up):** national top stories → "How does CT rank?" via
  one Data Commons call across 50 states. Shareable by construction.

## Why the AI is intentional

- LLM job #1: map headline → catalog indicator (closed set, JSON output).
- LLM job #2: phrase the question. Every proposal must pass a **dry-run
  validation** — if the query doesn't return data, the question is discarded.
- Everything numeric is fetched, not generated. Hallucination is
  structurally impossible in the answer; the failure mode is a missing card,
  never a wrong card.

## Rubric mapping

| Criterion | Our evidence |
|---|---|
| Problem clarity | CTData's own Data Helpline + newsletter; "last mile of attention" is CTData's stated mission gap |
| Solution quality | 2 streams, constrained generation, dry-run validation, live feed that grew during judging |
| AI effectiveness | LLM only where it's uniquely able (headline→indicator mapping), validated by execution; offline heuristic fallback proves the loop |
| Research and evidence | Every endpoint tested live on 2026-09-30 (see data_sources.md, incl. what FAILED); cards built from real fetched values |
| Impact potential | Drop-in content for CTData's existing weekly newsletter; election-season demo with Nov 3, 2026 imminent |
| Presentation | 3-min demo: a card generated from that morning's headline, provenance chain shown, "asked-log" dedupe live |
